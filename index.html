HanaLima is a native SwiftUI app that drives limactl. Size your CPUs, memory and disks, wire up NAT, host-only and bridged networks with fixed IPs, and live in a real console — no root, no socket_vmnet, no sudoers file. HanaLima は limactl を操作するネイティブの SwiftUI アプリです。CPU・メモリ・ディスクを割り当て、NAT・ホストオンリー・ブリッジのネットワークを固定 IP 付きで組み、そのままコンソールで作業できます。root も socket_vmnet も sudoers も要りません。

// how it works

What makes HanaLima possibleHanaLima だからできること、その理由

No magic and no kernel extensions: a handful of macOS APIs used in a way most tools don't, plus some careful plumbing around Lima's public interfaces. 魔法もカーネル拡張もありません。多くのツールが使っていない macOS の API の使い方と、Lima の公開インターフェースまわりの丁寧な配管だけです。

01

macOS 26 vmnet_network + one entitlement = rootless NAT with your subnetmacOS 26 の vmnet_network と entitlement 1 つで、root なしの NAT

The new vmnet API lets a process create a NAT or host-only network with a subnet you choose and DHCP reservations — as an ordinary user, as long as the binary is signed with com.apple.security.virtualization. Without it you get error 1002.新しい vmnet API なら、サブネットを指定した NAT やホストオンリーのネットワークを、DHCP 予約付きで一般ユーザーのまま作れます。条件は、バイナリが com.apple.security.virtualization 付きで署名されていること。無いとエラー 1002 になります。

hanalima-netd 
let cfg = vmnet_network_configuration_create(
    .VMNET_SHARED_MODE, &st)
// the gateway (.1), not the network (.0)
vmnet_network_configuration_set_ipv4_subnet(
    cfg, &gw, &mask)
vmnet_network_configuration_add_dhcp_reservation(
    cfg, mac, &ip)
let net = vmnet_network_create(cfg, &st)
// uid 501 · no sudo
02

Bridging to the LAN — also without rootLAN へのブリッジも root なし

The classic bridged mode is what socket_vmnet runs as root. We found that, with the same entitlement, vmnet_start_interface in VMNET_BRIDGED_MODE starts fine as uid 501. One interface per VM; two VMs plus en0 share bridge100, and the Mac keeps its IPv4.従来のブリッジモードは、socket_vmnet が root で動かしているものです。同じ entitlement があれば、VMNET_BRIDGED_MODE の vmnet_start_interface が uid 501 のまま起動することを確かめました。VM ごとにインターフェースを作り、2 台の VM と en0 が bridge100 を共有しても、Mac の IPv4 は維持されます。

bridge · en0 
let desc = xpc_dictionary_create(nil, nil, 0)
xpc_dictionary_set_uint64(desc, vmnet_operation_mode_key,
                          VMNET_BRIDGED_MODE)
xpc_dictionary_set_string(desc,
    vmnet_shared_interface_name_key, "en0")
vmnet_start_interface(desc, queue) { status, params in … }
// uid 501 · status 1000 (VMNET_SUCCESS)
03

Speaking socket_vmnet's protocol, so Lima needs no patchessocket_vmnet のプロトコルを話すので、Lima は無改造

Lima already knows how to plug a VM into a UNIX socket: networks: - socket: PATH. The protocol is QEMU's stream format — a 4-byte big-endian length, then the frame. hanalima-netd speaks it on one side and vmnet on the other. Works for VZ and QEMU VMs.Lima はもともと、VM を UNIX ソケットにつなげます（networks: - socket: PATH）。中身は QEMU の stream 形式で、4 バイトのビッグエンディアンの長さに続けてフレームを送るだけ。hanalima-netd は片側でこれを話し、反対側で vmnet を話します。VZ でも QEMU でも動きます。

lima.yaml 
# ~/.lima/dev/lima.yaml (written via limactl edit --set)
networks:
  - socket: "~/Library/Application Support/
      HanaLima/net/lan.sock"

# on the wire
[00 00 05 ea][ ethernet frame, 1514 bytes … ]
04

launchd socket activation: networks outlive the applaunchd のソケットアクティベーションで、アプリが無くても動く

Each network is a per-user LaunchAgent whose socket launchd owns. The helper starts on the first VM connection and exits when idle. Quit HanaLima, run limactl start from a shell — the network is still there.ネットワークごとにユーザーの LaunchAgent を登録し、ソケットは launchd が持ちます。最初の VM 接続でヘルパーが起動し、使われなくなると終了します。HanaLima を終了して、シェルから limactl start しても、ネットワークはそのまま使えます。

LaunchAgent

05

Fixed IPs that actually stick: DHCP option 61 surgery固定 IP を本当に効かせる、DHCP オプション 61 の手術

vmnet reserves addresses by MAC, but macOS's bootpd identifies a client by its client identifier when one is present — and Linux guests send a DUID. So the reservation never matched. The helper strips option 61 from DHCP requests, only for MACs that have a reservation.vmnet の予約は MAC で行いますが、macOS の bootpd はクライアント識別子があればそちらで識別し、Linux のゲストは DUID を送ってきます。そのため予約が一致しませんでした。ヘルパーは、予約のある MAC からの DHCP 要求に限って、オプション 61 を取り除きます。

DHCPClientIDFilter 
// VM → vmnet, per frame
if reservedMACs.contains(srcMAC),
   let fixed = DHCPClientIDFilter
       .strippingClientIdentifier(from: frame) {
    send(fixed)      // bootpd now matches by MAC
}
// lima0: 192.168.200.10 — boot after boot
06

limactl is the API — and edits stay minimallimactl を API として使い、変更は最小限に

No Go code is linked; HanaLima reads limactl list --format json and the watch --json event stream. Form edits become limactl edit --set expressions for just the fields you touched, so Lima's defaults and your unknown keys survive, and Lima validates every change.Go のコードはリンクせず、limactl list --format json と watch --json のイベントを読みます。フォームの変更は、触った項目だけの limactl edit --set 式になるので、Lima の既定値や未知のキーは残り、変更はすべて Lima が検証します。

LimaKit 
$ limactl edit dev --set '.cpus = 4' \
                 --set '.memory = "8GiB"'
$ limactl watch --json
{"instance":"dev","status":{"running":true,
 "sshLocalPort":60022}}

// battle scars

Bugs we hit, so you don't have to戦いの記録：踏んだ不具合と、その回避

The vmnet API is young. Here is what bit us on macOS 27.0.1, and how HanaLima's helper is built around it. Full notes are in the repository. vmnet の API はまだ若く、macOS 27.0.1 でいくつも不具合を踏みました。HanaLima のヘルパーは、それを前提に作られています。詳しい記録はリポジトリにあります。

Reusing a network ate the Mac's IPv4ネットワークの使い回しで、Mac の IPv4 が消えた

A vmnet_network reused after its interface stopped takes over a bridged interface's bridge100, detaches en0, and the host loses its IPv4 address. Reported to Apple as FB25122122, with a standalone repro.インターフェースを止めた vmnet_network を再利用すると、ブリッジの bridge100 を奪って en0 を外し、ホストの IPv4 が消えます。再現ツール付きで Apple に FB25122122 として報告しました。

Create networks on the first VM connection, release them on the last. Never reuse.ネットワークは最初の接続で作り、最後の切断で解放。使い回さない。

Idle networks forget DHCP reservationsアイドルのネットワークは DHCP 予約を忘れる

Once its last interface stops, a network silently drops reservations and port-forward rules, even while you hold the ref (forum thread 847642, FB24895271).最後のインターフェースが止まると、ref を持っていても予約とポート転送の設定が黙って消えます（フォーラム 847642、FB24895271）。

Same fix: a fresh network per active period, rebuilt from networks.json.同じ対策：使う期間ごとに、networks.json から作り直す。

Exit without stopping = subnet held hostage止めずに終了すると、サブネットが人質に

If a process exits with an interface still started, vmnet keeps the subnet reserved for hours (or until reboot), and every create fails with 1001. A main-actor signal handler crashing with SIGTRAP made this happen on every SIGTERM.インターフェースを開始したままプロセスが終わると、そのサブネットは数時間（か再起動まで）予約されたままになり、作成が 1001 で失敗し続けます。main actor 扱いのシグナルハンドラが SIGTRAP で落ちて、SIGTERM のたびにこれが起きていました。

@Sendable handlers; every exit path stops interfaces first.ハンドラは @Sendable に。すべての終了経路で、先にインターフェースを止める。

launchd pins your helper's cdhashlaunchd はヘルパーの cdhash を覚えている

Overwrite the helper with a new build and the already-registered LaunchAgent fails to spawn (exit 78, EX_CONFIG) — while the old process keeps running, so you won't notice until it restarts.ヘルパーを新しいビルドで上書きすると、登録済みの LaunchAgent が起動できなくなります（終了コード 78）。古いプロセスは動き続けるので、再起動するまで気づきません。

Content-addressed copies (hanalima-netd-<hash>); agents move over only while idle.内容のハッシュ付きの名前で別々に置き、エージェントはアイドルのときだけ移す。

A live snapshot that "succeeds" but saves nothing成功したのに何も保存されないスナップショット

On a running QEMU VM, Lima sends HMP savevm; QEMU refuses while a 9p share is mounted, yet limactl exits 0. And a failed loadvm leaves the VM frozen in restore-vm until someone sends QMP cont.実行中の QEMU の VM では、Lima は HMP の savevm を送ります。9p の共有があると QEMU は拒否しますが、limactl は終了コード 0。さらに loadvm に失敗すると、QMP の cont を送るまで VM は restore-vm で止まったままです。

Snapshot only while stopped (qemu-img path), and verify the tag exists afterwards.停止中（qemu-img の経路）だけで操作し、作成後にタグがあるかを確かめる。

Window restoration wins over .defaultLaunchBehaviorウィンドウの復元は .defaultLaunchBehavior より強い

Quit a menu-bar app with its window closed, and macOS faithfully restores "no window" next time — even with .defaultLaunchBehavior(.presented) and .restorationBehavior(.disabled). The app looked like it never launched.ウィンドウを閉じたままメニューバーのアプリを終了すると、次の起動で macOS は「ウィンドウなし」を忠実に復元します。.defaultLaunchBehavior(.presented) や .restorationBehavior(.disabled) を付けても同じで、起動していないように見えました。

The menu bar label — which always exists — opens the window on launch if none is visible.常に存在するメニューバーのラベルが、起動時にウィンドウがなければ開く。

From zero to a VM on your LANゼロから、LAN に参加する VM まで

No signed release yet — build from source. You need macOS 26+, Xcode 26+ with the Metal Toolchain, and Homebrew.署名済みのリリースはまだありません。ソースからビルドしてください。必要なものは macOS 26 以降、Metal Toolchain 入りの Xcode 26 以降、Homebrew です。

  1. Install LimaLima を入れる

    Plus the extra guest agents for non-native architectures.別アーキテクチャ用の追加ゲストエージェントも一緒に。

  2. Build the appアプリをビルド

    The script assembles build/HanaLima.app, signs the network helper with the virtualization entitlement, and signs the app ad hoc.スクリプトが build/HanaLima.app を組み立て、ネットワークのヘルパーに仮想化の entitlement を付けて署名し、アプリを ad-hoc 署名します。

  3. Create a VMVM を作る

    ＋ in the sidebar → pick a template → create. The first start downloads the image.サイドバーの ＋ → テンプレートを選んで作成。最初の起動でイメージをダウンロードします。

  4. Add a bridged networkブリッジのネットワークを追加

    Networks → ＋ → Bridge → en0. Then add a NIC for it in the VM's Settings → Network. No password prompt.ネットワーク → ＋ → ブリッジ → en0。VM の設定 → ネットワークで NIC を追加します。パスワードは聞かれません。

Hana lima — handmadeHana lima ── 手作り
