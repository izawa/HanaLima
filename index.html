HanaLima is a native SwiftUI app that drives limactl. Size your CPUs, memory and disks, wire up NAT, host-only and bridged networks with fixed IPs, and live in a real console — no root, no socket_vmnet, no sudoers file. HanaLima は limactl を操作するネイティブの SwiftUI アプリです。CPU・メモリ・ディスクを割り当て、NAT・ホストオンリー・ブリッジのネットワークを固定 IP 付きで組み、そのままコンソールで作業できます。root も socket_vmnet も sudoers も要りません。

// how it works

What makes HanaLima possibleHanaLima だからできること、その理由

No magic and no kernel extensions: a handful of macOS APIs used in a way most tools don't, plus some careful plumbing around Lima's public interfaces. 魔法もカーネル拡張もありません。多くのツールが使っていない macOS の API の使い方と、Lima の公開インターフェースまわりの丁寧な配管だけです。

01

macOS 26 vmnet_network + one entitlement = rootless NAT with your subnetmacOS 26 の vmnet_network と entitlement 1 つで、root なしの NAT

The new vmnet API lets a process create a NAT or host-only network with a subnet you choose and DHCP reservations — as an ordinary user, as long as the binary is signed with com.apple.security.virtualization. Without it you get error 1002.新しい vmnet API なら、サブネットを指定した NAT やホストオンリーのネットワークを、DHCP 予約付きで一般ユーザーのまま作れます。条件は、バイナリが com.apple.security.virtualization 付きで署名されていること。無いとエラー 1002 になります。

hanalima-netd
02

Bridging to the LAN — also without rootLAN へのブリッジも root なし

The classic bridged mode is what socket_vmnet runs as root. We found that, with the same entitlement, vmnet_start_interface in VMNET_BRIDGED_MODE starts fine as uid 501. One interface per VM; two VMs plus en0 share bridge100, and the Mac keeps its IPv4. Works over Wi-Fi too: bridged to en1, a VM got its address from the LAN's DHCP and reached the router through the access point.従来のブリッジモードは、socket_vmnet が root で動かしているものです。同じ entitlement があれば、VMNET_BRIDGED_MODE の vmnet_start_interface が uid 501 のまま起動することを確かめました。VM ごとにインターフェースを作り、2 台の VM と en0 が bridge100 を共有しても、Mac の IPv4 は維持されます。Wi-Fi でも動きます。en1 にブリッジした VM が LAN の DHCP からアドレスを取得し、アクセスポイント経由でルーターまで届きました。

bridge · en0 / Wi-Fi
03

Speaking socket_vmnet's protocol, so Lima needs no patchessocket_vmnet のプロトコルを話すので、Lima は無改造

Lima already knows how to plug a VM into a UNIX socket: networks: - socket: PATH. The protocol is QEMU's stream format — a 4-byte big-endian length, then the frame. hanalima-netd speaks it on one side and vmnet on the other. Works for VZ and QEMU VMs.Lima はもともと、VM を UNIX ソケットにつなげます（networks: - socket: PATH）。中身は QEMU の stream 形式で、4 バイトのビッグエンディアンの長さに続けてフレームを送るだけ。hanalima-netd は片側でこれを話し、反対側で vmnet を話します。VZ でも QEMU でも動きます。

lima.yaml
04

launchd socket activation: networks outlive the applaunchd のソケットアクティベーションで、アプリが無くても動く

Each network is a per-user LaunchAgent whose socket launchd owns. The helper starts on the first VM connection and exits when idle. Quit HanaLima, run limactl start from a shell — the network is still there.ネットワークごとにユーザーの LaunchAgent を登録し、ソケットは launchd が持ちます。最初の VM 接続でヘルパーが起動し、使われなくなると終了します。HanaLima を終了して、シェルから limactl start しても、ネットワークはそのまま使えます。

LaunchAgent
05

Fixed IPs that actually stick: DHCP option 61 surgery固定 IP を本当に効かせる、DHCP オプション 61 の手術

vmnet reserves addresses by MAC, but macOS's bootpd identifies a client by its client identifier when one is present — and Linux guests send a DUID. So the reservation never matched. The helper strips option 61 from DHCP requests, only for MACs that have a reservation.vmnet の予約は MAC で行いますが、macOS の bootpd はクライアント識別子があればそちらで識別し、Linux のゲストは DUID を送ってきます。そのため予約が一致しませんでした。ヘルパーは、予約のある MAC からの DHCP 要求に限って、オプション 61 を取り除きます。

DHCPClientIDFilter
06

limactl is the API — and edits stay minimallimactl を API として使い、変更は最小限に

No Go code is linked; HanaLima reads limactl list --format json and the watch --json event stream. Form edits become limactl edit --set expressions for just the fields you touched, so Lima's defaults and your unknown keys survive, and Lima validates every change.Go のコードはリンクせず、limactl list --format json と watch --json のイベントを読みます。フォームの変更は、触った項目だけの limactl edit --set 式になるので、Lima の既定値や未知のキーは残り、変更はすべて Lima が検証します。

LimaKit
07

A VM's disk on an external drive — and back, anytimeVM のディスクを外付けドライブへ、いつでも行き来

Lima has no per-VM location, and it lists only real folders in ~/.lima: link a whole VM folder to another drive and the VM vanishes. So the folder stays and only disk, the one large file, moves out as a link Lima follows for start, resize and snapshots. The copy goes through copyfile with COPYFILE_DATA_SPARSE, which copies only the data extents, so the disk keeps its sparse size. The swap to the link is a single rename, so a failed or cancelled move leaves the original untouched.Lima には VM ごとの置き場所の設定がなく、一覧には ~/.lima の中の本物のフォルダしか出ません。VM のフォルダごと別のドライブへリンクすると、VM が消えてしまいます。そこでフォルダは残し、いちばん大きな disk だけをリンクで外へ出します。起動、拡張、スナップショットも Lima がリンクをたどってくれます。コピーは copyfile の COPYFILE_DATA_SPARSE で、データのある範囲だけを写すので、ディスクはスパースのままです。リンクへの置き換えは rename 1 回なので、失敗しても中止しても元のディスクは無傷です。

ExternalDisk
// networking

The packet pathパケットの通り道

One helper process per network, one vmnet interface per VM. NAT and host-only networks are created on the first connection and released on the last — never reused, because a reused vmnet network can lose its DHCP reservations and even take the Mac's IPv4 with it. ネットワークごとにヘルパーが 1 プロセス、VM ごとに vmnet のインターフェースが 1 つ。NAT とホストオンリーのネットワークは最初の接続で作り、最後の切断で解放します。使い回しはしません。使い回した vmnet のネットワークは DHCP 予約を失い、Mac の IPv4 まで奪うことがあるためです。

v0.1

Create & run作成と運用

Pick from all of Lima's templates, grouped by distribution with readable names — “Ubuntu 24.04 LTS”, “Debian (Latest: 13)”. Then CPUs, memory, disk, VZ or QEMU. Live state via limactl watch, and image downloads with percent, speed and time left — even though limactl prints no progress without a terminal.Lima のテンプレートを、ディストリビューションごとに「Ubuntu 24.04 LTS」「Debian（最新: 13）」のような名前で選べます。CPU、メモリ、ディスク、VZ／QEMU も選んで作成。limactl watch で状態をリアルタイム表示。イメージのダウンロードは、割合・速度・残り時間まで（端末なしでは limactl が進捗を出さないので、キャッシュの書き込みから計算）。

v0.1

Console that waits待ってくれるコンソール

v0.2

Settings, form or YAML設定はフォームでも YAML でも

NICs, shared folders, port forwards, or the raw lima.yaml — validated by Lima before it lands. While the VM runs, everything stays readable, just not editable.NIC、共有フォルダ、ポート転送。lima.yaml を直接編集しても、Lima の検証を通ってから反映されます。VM の実行中も、変更はできませんが内容はすべて閲覧できます。

v0.2

Disks, storage & external drivesディスク、使用量、外付けドライブ

Create, grow, delete and attach disks with limactl disk. See where Lima keeps VMs and downloaded images, the space each really uses (sparse-aware, like du), and which VM uses each downloaded image. Clear the ones no VM needs — Lima's own prune --keep-referred keeps anything a template mentions, so HanaLima decides itself. Keep a temporary VM's disk on an external drive: HanaLima checks the drive first (another volume, APFS, free space), moves only the disk while keeping it sparse, stops the VM from starting while the drive is away, and cleans up when you delete the VM.limactl disk でディスクの作成、拡張、削除、接続。VM やダウンロードしたイメージの置き場所と、実際に使っている容量（du と同じくスパースを考慮）、ダウンロードしたイメージをどの VM が使っているかを表示。どの VM も使っていないイメージだけを削除できます（Lima の prune --keep-referred はテンプレートが参照するものも残すので、HanaLima が自分で判定）。一時的な VM のディスクは外付けドライブへ。移動先を先に確かめ（別のボリューム、APFS、空き容量）、ディスクだけをスパースのまま移し、ドライブが外れていれば起動を止め、VM の削除で後片付けまで行います。

v0.2

Menu bar & start at loginメニューバーとログイン時の起動

Every VM one click away; keeps running when the window closes. Per-VM start at login via limactl autostart.すべての VM にワンクリックで。ウィンドウを閉じても常駐。VM ごとのログイン時の起動は limactl autostart で。

v0.3

Rootless networksroot 不要のネットワーク

NAT and host-only with your subnet and fixed IPs; bridged to wired or Wi-Fi. Change or delete a network and each VM on it is told what to do next — restart, or drop a NIC that points nowhere. VMs on Lima's classic socket_vmnet networks keep working.サブネットと固定 IP を指定できる NAT とホストオンリー、有線・Wi-Fi へのブリッジ。ネットワークを変更・削除すると、それを使う VM ごとに次の操作（再起動、行き先のない NIC の削除）を案内。Lima の従来方式（socket_vmnet）を使う VM もそのまま動きます。

v0.4

Snapshots & thumbnailsスナップショットとサムネイル

Save, restore and delete disk snapshots of QEMU VMs (while stopped — see below). A live view of the screen for VZ VMs with a display, via limactl screenshot.QEMU の VM のディスクを、停止中に保存・復元・削除（理由は下で）。画面を有効にした VZ の VM は、limactl screenshot で画面を概要に表示。

v0.4

Logs & provisioningログとプロビジョニング

Follow the host agent log and serial consoles live, with search. Edit the provisioning scripts and data files Lima applies on every boot — in an editor that won't smart-quote your shell script.ホストエージェントのログとシリアルコンソールを、検索しながらリアルタイムに。Lima が起動のたびに適用するスクリプトやファイルも、スマート引用符に化けないエディタで編集。

v0.4

English & Japanese英語と日本語

The whole UI — menus, sheets, error messages, plurals — in both languages, from a String Catalog. HanaLima follows your Mac's language, or pick one per app in System Settings.メニュー、シート、エラーメッセージ、複数形まで、UI のすべてを両方の言語で（String Catalog）。Mac の言語設定に従います。システム設定で HanaLima だけ別の言語にもできます。

// quick start

From zero to a VM on your LANゼロから、LAN に参加する VM まで

No signed release yet — build from source. You need macOS 26+, Xcode 26+ with the Metal Toolchain, and Homebrew.署名済みのリリースはまだありません。ソースからビルドしてください。必要なものは macOS 26 以降、Metal Toolchain 入りの Xcode 26 以降、Homebrew です。

  1. Install LimaLima を入れる

    Plus the extra guest agents for non-native architectures.別アーキテクチャ用の追加ゲストエージェントも一緒に。

  2. Build the appアプリをビルド

    The script builds a release, signs the network helper with the virtualization entitlement, signs the app ad hoc for your Mac, installs it into /Applications and opens it. Run it again to update.スクリプトがリリースビルドを作り、ネットワークのヘルパーに仮想化の entitlement を付けて署名し、アプリをこの Mac 用に ad-hoc 署名して、/Applications に入れて起動します。更新するときも同じコマンドです。

  3. Create a VMVM を作る

    ＋ New VM in the sidebar → pick a template (e.g. Ubuntu 24.04 LTS) → Create. The first start downloads the image.サイドバーの ＋ 新規仮想マシン → テンプレート（例: Ubuntu 24.04 LTS）を選んで作成。最初の起動でイメージをダウンロードします。

  4. Add a bridged networkブリッジのネットワークを追加

    Networks → ＋ → Bridge → en0. Then Add NIC in the VM's Settings tab. No password prompt.ネットワーク → ＋ → ブリッジ → en0。VM の設定タブの「NIC を追加」で選びます。パスワードは聞かれません。

Hana lima — handmadeHana lima ── 手作り

In Hawaiian, hana means to make and lima means hand — and also five. The icon is a plumeria, Hawaii's five-petaled lei flower (and hana sounds like 花, "flower", in Japanese). Each petal is a VM, with vents and a status LED, built by hand around a glowing network core with a >_ prompt. ハワイ語で hana は「作る」、lima は「手」、そして「5」。アイコンは、ハワイのレイに使われる 5 弁の花・プルメリアです（hana は日本語の「花」とも響きます）。花びらの一枚一枚が、通気口と LED を持つ VM。>_ の光るネットワークの芯のまわりに、手で組み上げていきます。
