vmType: hanalima の前後 — レイヤー図で見る HanaLima の構成

2026-11-05。Lima の外部ドライバーの仕組みで lima-driver-hanalima を持ったことで、HanaLima が「Lima の外から操作する GUI」から「VM 本体を自分で持つ層」に変わった。これまでの実装（docs/09 の段階 0〜4）はこの土台の上にあり、今後の実装もここを前提にするので、前後の層の違いを 1 枚に残す。

1. レイヤー図

HanaLima が持つLima が持つmacOS（Virtualization.framework）

2. 何がどちらの層に移ったか

関心事実装前（vz）実装後（hanalima）それで何ができたか
VM の構成と起動・停止Lima の vz（hostagent 内）ドライバー（ドライバーのプロセス。アプリとは別）以下すべての前提
NIC 0（usernet）必ず付く（外す設定なし）つなぐかどうかを選べる（vmOpts.hanalima.usernet: false。NIC 自体は cidata が eth0 を名指しするので付けたままつながない）隔離プロファイル（Mac・LAN・インターネットに届かない VM。届くのは足した NIC の先だけ）
SSH の経路usernet の転送（vsock は後から乗り換え）同じ順序（usernet → vsock 22 を 1 回確かめて乗り換え）。usernet が無ければ vsock だけを応えるまで探すネットワークの無い VM にも SSH・ゲストエージェント・ポート転送が通る。起動中に vsock を探り続けるとゲストエージェントの vsock が不安定になるので、並走はしない
シリアルポート書き込み専用のログ双方向（serialv.sock）コンソールタブの「シリアル」。sshd を壊した VM に入る 2 つ目の経路
画面hostagent のウインドウ、閉じたら戻せないドライバーのウインドウ、隠す/開き直す「画面を開く」、サムネイル（limactl screenshot 不要）
HanaLima → VM の要求limactl の語彙だけ側道（hanalima-ctl.sock、JSON）Lima に無い操作を足せる（今後: 一時停止など）
追加ディスク・virtiofs・ゲストエージェントLima の vzドライバー（同じ振る舞いを再実装）Lima の vz と同等（E2E で確認）
イメージ · cloud-init · ポート転送 · list/watch · clone · editLimaLima（変更なし）Lima の安定した外側だけに依存する方針はそのまま
既存 VM との互換—disk/vz-efi/vz-identifier が共通limactl edit --set '.vmType = "hanalima"' だけで移行、戻すのも同じ
HanaLima が無い Mac動くhanalima の VM は起動しない（vz に戻せば動く）既定は hanalima（2026-11-06）。HanaLima の無い Mac へ持っていくなら vz に戻す（設定タブで 1 手順）
VM 同士だけのネットワーク（段階 5）無い（vmnet はどの種類でも Mac が参加する）netd のゲスト専用モード（vmnet なしの L2 スイッチ＋自前の DHCP/ARP。ドライバーとは別の層）隔離プロファイルの VM 同士をつなぐ。Lima の vz の VM でも使える

3. 今後の実装のために

  • Lima との境界は gRPC（driver.proto）と cidata の約束だけ。 Lima 2.2.1 の外部ドライバー API は実験的（版ごとに差分を追う）。ドライバー側で埋める既定値（mountType・ssh.overVsock・vmOpts.vz・dns、隔離では param.internal_netplanOptional・hostResolver.enabled=false・containerd オフ・dns を最初のゲスト専用ネットワークの DNS に）は Configure に集めてある。Configure の結果はメモリ上だけで lima.yaml には書かれないので、設定タブの NIC 0 の下と概要タブのユーザーモードの行に「ドライバーが起動時に切る」旨の注記を出す（2026-11-06）。
  • Lima の RPC に無い操作は側道で足す。 RunGUI（10 秒の制限）と limactl screenshot（内部ドライバー限定）が使えなかったので生まれた仕組み。一時停止・saveMachineState・ゲスト専用スイッチなども同じ経路に乗せられる。ただし Lima から見える状態（Running/Stopped）と食い違う操作は、Lima の list/watch をどう見せるかまで決めてから。
  • ドライバー独自の設定は vmOpts.hanalima に置く。 Lima は vmOpts を map[VMType]any として保存し、limactl edit でも残る。最初の鍵は usernet: false。
  • vz ⇄ hanalima の往復を常に保つ。 ディスクの形式（raw）、EFI の変数ストア、マシン識別子を vz と同じにしておくことが、vz に戻せる安全弁。ドライバーだけが使うファイルは hanalima* の名前にする。
  • ゲスト側に何かを入れる必要があるものは、プロビジョニングの例で。 hvc0 の getty（シリアルからのログイン）がその形。vsock の sshd は systemd 256 以降なら何も要らず、Alpine や古い systemd には BootScripts RPC で socat の中継を入れる（網が要るので、NIC 0 付きで一度起動してから隔離に切り替える。作成画面のプリセットがその順を自動にする）。Rosetta の起動スクリプトも同じ経路。
  • 停止は後片付けの完了まで返さない。 Lima は Stop が返ると hostagent を終え、ドライバーに SIGTERM を送る。デリゲート経由の後片付け（usernet の終了、pid・ソケットの削除）の途中で exit すると残骸が出るので、stop() は run == nil && !busy まで待つ。
  • アプリ本体は VM を持たない。 救出起動と ISO インストールもドライバーの hosted モード（--hosted、gRPC なし、制御ソケットと hanalima-hosted.pid）で動く。アプリは起動して見ているだけなので、終了しても VM は残り、次の起動で再接続する。VZ を触る場所がドライバー 1 つになった。
  • 隔離は 2 つの層の組み合わせ。 VM をホストから切るのはドライバーの隔離プロファイル（usernet なし、SSH は vsock）、切った VM 同士をつなぐのは netd のゲスト専用ネットワーク（vmnet なしの L2 スイッチ。DHCP は経路を配らず、DNS は lima-<名前> だけに答える）。後者は Lima の vz の VM にも付くが、vz には usernet が残るので隔離にはならない（docs/06 §8）。
  • 済んだもの（2026-11-06 時点）: Rosetta（vz と同じ共有と起動スクリプト）、lima: のネットワーク（socket_vmnet は socket: と同じ中継、最初の user-v2 は NIC 0 の usernet の代わり）、スナップショットの RPC（limactl snapshot がアプリと同じ DiskSnapshot を使う）、ゲスト専用ネットワークの DNS（netd が lima-<名前> だけに答える）、古いヘルパーで動く VM の印（staleHelpers）、DriverInstaller（同梱のドライバーを <prefix>/lib/lima/ に写し、ターミナルの limactl からも使える）、新規作成の既定を hanalima に。隔離プロファイルは E2E（DriverIsolationEndToEndTests）と docs/06 §7 まで、ゲスト専用ネットワークは GuestOnlyEndToEndTests と docs/02 まで済み。ドライバーの E2E は Alpine・Ubuntu LTS・Fedora・Debian で通過。残っているもの: 一時停止（saveMachineState）、macOS ゲスト、Lima 2.3 の driver.proto への追従（正式リリース待ち）、Alpine の追加ディスクの揺らぎ（Lima の mdev の競合、upstream 報告の要否）、vsock 探索の設計メモ、取り残されたドライバーの原因（番犬で回避済み）。
