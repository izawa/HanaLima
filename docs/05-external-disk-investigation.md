# VM のディスクを外付けドライブに置く（調査結果）

調査日: 2026-10-11 / 環境: macOS 27.0.1 (Apple Silicon), Lima 2.2.1

## 1. 目的

常用しない一時的な VM（検証用の Ubuntu など）について、大きなファイルを内蔵ディスクではなく外付けの大容量ドライブに置きたい。Lima には VM ごとの置き場所の設定がないため、`~/.lima` の中にシンボリックリンクを置き、実体を外に置く構成で、Lima のすべての操作がリンクをたどってくれるかを調べた。

## 2. 結論

- **VM のフォルダ（`~/.lima/<名前>`）ごとリンクにする方式は使えない。** `limactl list` に出なくなる（HanaLima からも見えなくなる）。
- **フォルダは `~/.lima` のまま、ディスクのファイル `disk` だけを外に置いてリンクにする方式は使える。** VZ・QEMU とも、起動、シェル、設定の変更、ディスクの拡張、停止中のスナップショットまで動いた。VM の大きなファイルは `disk` だけなので、内蔵ディスクに残るのは十数 MB になる。
- 移すときは **`rsync --sparse`** を使う。`mv`・`cp`・`ditto` でボリュームをまたぐと、スパースファイルの穴が実データとしてコピーされ、ディスクの名目サイズ（例: 10 GB）を丸ごと消費する。

## 3. 方法

外付けドライブの代わりに、スパース形式のディスクイメージで別の APFS ボリューム（`/Volumes/LimaTest`）を作ってマウントした。同じボリューム内ではなく別ボリュームにしたのは、ボリュームをまたぐときの挙動（APFS のクローンが使えないなど）も実際に近づけるため。テスト用の VM は Alpine（`hanalima-e2e-*`）で、終了後に VM、ボリューム、イメージを削除した。

## 4. VM のフォルダごとリンクにする

作成した VM（停止中）のフォルダを外へ移し、`~/.lima/<名前>` にリンクを置いた。

| 操作 | 結果 |
|---|---|
| `limactl list`（名前指定も含む） | **出ない**（`No instance matching … found`）。一覧は `~/.lima` の中の本物のディレクトリだけを数えているとみられる |
| `limactl start <名前>` | 起動する（READY まで） |
| `limactl shell`、`stop`、`edit --set` | 動く。`lima.yaml` はリンク先に書き込まれ、リンクも保たれる |
| ソケットとログ | すべてリンク先に作られる。hostagent はリンクのままのパス（`~/.lima/<名前>/ha.sock` など）を使うので、UNIX ソケットのパス長の問題は起きない |
| `limactl delete` | **リンクだけが消え、外の実体は残る** |
| 作成前にリンクを用意（リンク先は空のフォルダ） | 失敗: `instance … already exists` |
| 作成前にリンクを用意（リンク先が存在しない） | 失敗: `mkdir …: file exists` |

一覧に出ないため、`limactl list` を使う HanaLima では扱えない。

## 5. ディスクのファイルだけをリンクにする

作成した VM（停止中）の `~/.lima/<名前>/disk` を外へ移し、同じ場所にリンクを置いた。

| 操作 | VZ | QEMU |
|---|---|---|
| ディスクのファイル構成 | `disk` 1 つ | `disk` 1 つ |
| `limactl list` | 出る | 出る |
| 起動、シェル | 動く | 動く（起動中にゲストエージェントの転送の警告が出たが READY まで進んだ。通常の QEMU VM でも出るかは未比較） |
| `edit --set '.disk = "12GiB"'`（拡張） | 動く。リンクは保たれ、ゲストのルートも 11.3 GB に広がった | 未確認 |
| 停止中のスナップショット（`qemu-img`） | — | 動く |
| `limactl delete` | リンクだけが消え、外のディスクは残る | 同じ |
| `~/.lima/<名前>` に残る量 | 約 19 MB | 同程度 |

### ボリュームをまたぐコピーとスパースファイル

実使用 約 230 MB、名目 10 GB の `disk` を別ボリュームへコピーしたときの使用量:

| 方法 | コピー先の使用量 |
|---|---|
| `mv` | 9.9 GB |
| `/bin/cp` | 9.7 GB |
| `ditto` | 9.7 GB |
| `rsync --sparse`（macOS の openrsync） | 229 MB |

## 6. 注意点

- 作成時は、Lima が `~/.lima/<名前>` の中にディスクを作るので、一時的には内蔵ディスクを使う。外へ移すのは作成後（停止中）。
- OS イメージのキャッシュ（`~/Library/Caches/lima`）は内蔵のまま。使い終わったら、HanaLima の「使用量」で未使用のイメージを削除できる。
- 外付けドライブは APFS でフォーマットする（exFAT などはスパースファイルを扱えず、ディスクの名目サイズを丸ごと使う）。
- VM の実行中にドライブを取り外さない。ログイン時の自動起動にも使わない。
- HanaLima の「使用量」は、リンクの先を数えない（外に置いたディスクは表示されない）。

## 7. 手作業での手順

VM を作成して停止したあと（例: VM 名 `ubuntu-test`、外付けドライブ `/Volumes/HDD`）:

```bash
mkdir -p /Volumes/HDD/lima-disks/ubuntu-test
rsync --sparse ~/.lima/ubuntu-test/disk /Volumes/HDD/lima-disks/ubuntu-test/disk \
  && rm ~/.lima/ubuntu-test/disk \
  && ln -s /Volumes/HDD/lima-disks/ubuntu-test/disk ~/.lima/ubuntu-test/disk
```

VM を削除したあとは、`/Volumes/HDD/lima-disks/ubuntu-test` を手で削除する。

## 8. HanaLima の機能にする場合の案（2026-10-12 に実装済み。設計は [04](04-design.md)）

- VM の設定に「ディスクの場所」を設け、「別の場所へ移す…」で移動先を選ぶ（停止の確認 → `rsync --sparse` → リンクの作成）。
- VM を削除するとき、外に置いたディスクも削除する（`limactl delete` はリンクしか消さないため）。
- リンク先が見つからない（ドライブが外れている）ときは、起動前に知らせる。
- 「使用量」に、外に置いたディスクを「外部」として表示する。
