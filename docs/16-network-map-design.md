# 構成図

2026-11-16 の設計。VM とネットワークのつながりを、研究でよく描くネットワーク図の形で見せる。最初の版は設定とリースから描く読み取り専用の図で、疎通を確かめた結果は重ねない（2 段目）。

## 1. 形

ネットワークを縦の線（バス）にし、VM を左に 1 行ずつ並べて、VM から横に配線する。つながっているバスとの交点にだけ点を打つ。点の無い交差はつながっていない。

- VM を行にしたので、台数が増えても下に伸びるだけで、30 台でも縦のスクロールで読める。VM を横に並べる形（最初のモック）は 5〜6 台で幅が足りなくなる
- 一番上の行は「この Mac」で、Mac が参加しているバスに配線する（NAT とホストオンリーはゲートウェイ、ブリッジはそのインターフェース）。ゲスト専用のバスには Mac の点が無い。この行とバスの名前は、スクロールしても上に残す
- バスの見出しに、名前、種類、外への出方を書く: NAT は「Mac 経由で外へ」、ホストオンリーは「外へは出ない」、ブリッジは「LAN そのもの」、ゲスト専用はルーターがあれば「<ルーターの VM> 経由」、無ければ「外へは出ない」。ルーターのアドレスに当たる VM が無ければ「ルーター <アドレス>（VM なし）」
- NIC 0（Lima のユーザーモード）と vzNAT は VM ごとに別の出口なので、バスにしない。VM の箱のすぐ右に札を付ける。隔離した VM は「NIC 0 なし」。vzNAT の VM どうしが同じセグメントにいるかは確かめていないので、つながっているようには描かない
- IP には出どころを添える: 予約（固定）、リース（実行中の VM の、期限の切れていないものだけ）。ブリッジの先の IP は LAN の DHCP が配るので HanaLima には分からず、出さない
- 削除したネットワークを指す NIC は「削除したネットワーク」のバスにつなぐ。HanaLima の外のソケット（手で書いた `socket:`）は、削除とは別の「ソケット」のバスにする。1 台の VM が同じネットワークに 2 つの NIC を持つときは、1 つの点にまとめ、図には最初の IP と残りの数（`+1`）を、右の欄には全部の MAC と IP を出す。リースは NIC の MAC で引き、MAC で見つからなければ VM の名前で引く
- ブリッジのネットワークに、別の種類だった頃の予約が残っていても使わない（ブリッジの IP は LAN の DHCP が配る）
- HanaLima のドライバーでは、最初の user-v2 のネットワークが NIC 0 の代わりになり、NIC 0 の MAC を使う。その NIC の MAC は lima.yaml の値と違うので出さない
- VM の状態はアプリの表示と同じにする（一時停止中は Lima から実行中に、休止中は停止中に見える）

## 2. バスの並び

配線が点なしでバスを横切る回数が少なくなるように、バスの並びを決める。ある行が横切る数は「つながっているいちばん右のバスまでにある、つながっていないバスの数」。全部の行（Mac を含む）の合計が最小の並びを選ぶ。バスが 7 本までなら全部の並びを調べ（5040 通り）、それより多ければ、つながる VM の多い順に並べる。同じ合計なら、つながる VM の多い順、名前の順で先のものにする（毎回同じ並びにするため）。

並びの探索は、どの行がどのバスにつながっているかだけで決まるので、答えを覚えておく（選ぶたびに画面を描き直すので、7 本で 5040 通りを毎回調べると重い）。

VM の行の並びはサイドバーと同じ（グループの順、その中の並び、グループに入っていない VM）。

## 3. 選んだとき

VM の行、Mac の行、バスの見出しを選べる。選んだものの配線を強調し（バスは色を付けて太くする）、ほかは薄くする。選んでいる間だけ右の欄に詳細を出す（図の幅を取らないため）。図の下には「点のある所でつながっている。設定とリースから描いた図で、通信が届くかは確かめていない」と出しておく。

- VM: 状態、仮想化方式、グループ、NIC ごとのネットワーク・MAC・IP（出どころつき）、名前（`lima-<名前>`。ゲスト専用では `.hanalima` 付きも引ける）、同じネットワークにいる VM、NIC 0 の有無
- バス: 種類、サブネット、ゲートウェイ（ゲスト専用では netd の DHCP と DNS のアドレス）、ルーター、外への出方、つながっている VM
- Mac: 参加しているネットワーク

## 4. 作り

- 図の中身（バス、行、点、並び）は AgentKit の `NetworkMap` が、VM の一覧、HanaLima のネットワーク、Lima のネットワーク、リースから作る。画面に依存しないので単体テストで確かめる。MCP の `inspect` から使う余地も残る
- 描画は SwiftUI のビューと `Path` で、配置は固定の寸法で自前に計算する。自動配置のエンジンや Web の図のライブラリは使わない（構成は「VM × ネットワーク」の形に決まっていて、表のように並べれば足りる）
- 置き場所はネットワークの画面で、ツールバーの切り替えで一覧と構成図を行き来する
- 画面確認: `HANALIMA_SNAPSHOT_SELECT=networks HANALIMA_SNAPSHOT_MAP=1`（`HANALIMA_SNAPSHOT_MAPSELECT=<VM かネットワークの名前>` で選んだ状態、`HANALIMA_SNAPSHOT_DARK=1` でダークモード）
