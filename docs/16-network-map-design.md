# 構成図

2026-11-16 の設計。VM とネットワークのつながりを、研究でよく描くネットワーク図の形で見せる。最初の版は設定とリースから描く読み取り専用の図で、疎通を確かめた結果は重ねない（2 段目）。

## 1. 形

ネットワークを縦の線（バス）にし、VM を左に 1 行ずつ並べて、VM から横に配線する。つながっているバスとの交点にだけ点を打つ。点の無い交差はつながっていない。

- VM を行にしたので、台数が増えても下に伸びるだけで、30 台でも縦のスクロールで読める。VM を横に並べる形（最初のモック）は 5〜6 台で幅が足りなくなる
- 一番上の行は「この Mac」で、Mac が参加しているバスに配線する（NAT とホストオンリーはゲートウェイ、ブリッジはそのインターフェース）。ゲスト専用のバスには Mac の点が無い。この行とバスの名前は、スクロールしても上に残す
- バスの見出しに、名前、種類、外への出方を書く: NAT は「Mac 経由で外へ」、ホストオンリーは「外へは出ない」、ブリッジは「LAN そのもの」、ゲスト専用はルーターがあれば「<ルーターの VM> 経由」、無ければ「外へは出ない」。ルーターのアドレスに当たる VM が無ければ「ルーター <アドレス>（VM なし）」
- NIC 0（Lima のユーザーモード）と vzNAT は VM ごとに別の出口なので、バスにしない。VM の箱のすぐ右に札を付ける。隔離した VM は「NIC 0 なし」。vzNAT の VM どうしが同じセグメントにいるかは確かめていないので、つながっているようには描かない
- IP には出どころを添える: 予約（固定）、リース（実行中の VM の、期限の切れていないものだけ）。ブリッジの先の IP は LAN の DHCP が配るので HanaLima には分からず、出さない
- 削除したネットワークを指す NIC は「削除したネットワーク」のバスにつなぐ。HanaLima の外のソケット（手で書いた `socket:`）は、削除とは別の「ソケット」のバスにする。1 台の VM が同じネットワークに 2 つの NIC を持つときは、1 つの点にまとめ、図には最初の IP と残りの数（`+1`）を、右の欄には全部の MAC と IP を出す。リースは NIC の MAC で引き、MAC で見つからなければ VM の名前で引く
- ブリッジのネットワークに、別の種類だった頃の予約が残っていても使わない（ブリッジの IP は LAN の DHCP が配る）
- HanaLima のドライバーでは、最初の user-v2 のネットワークが NIC 0 の代わりになり、NIC 0 の MAC を使う。その NIC の MAC は lima.yaml の値と違うので出さない
- VM の状態はアプリの表示と同じにする（一時停止中は Lima から実行中に、休止中は停止中に見える）

## 2. バスの並び

配線が点なしでバスを横切る回数が少なくなるように、バスの並びを決める。ある行が横切る数は「つながっているいちばん右のバスまでにある、つながっていないバスの数」。全部の行（Mac を含む）の合計が最小の並びを選ぶ。バスが 7 本までなら全部の並びを調べ（5040 通り）、それより多ければ、つながる VM の多い順に並べる。同じ合計なら、つながる VM の多い順、名前の順で先のものにする（毎回同じ並びにするため）。

並びの探索は、どの行がどのバスにつながっているかだけで決まるので、答えを覚えておく（選ぶたびに画面を描き直すので、7 本で 5040 通りを毎回調べると重い）。

VM の行の並びはサイドバーと同じ（グループの順、その中の並び、グループに入っていない VM）。

## 3. 選んだとき

VM の行、Mac の行、バスの見出しを選べる。選んだものの配線を強調し（バスは色を付けて太くする）、ほかは薄くする。選んでいる間だけ右の欄に詳細を出す（図の幅を取らないため）。図の下には「点のある所でつながっている。設定とリースから描いた図で、通信が届くかは確かめていない」と出しておく。

- VM: 状態、仮想化方式、グループ、NIC ごとのネットワーク・MAC・IP（出どころつき）、名前（`lima-<名前>`。ゲスト専用では `.hanalima` 付きも引ける）、同じネットワークにいる VM、NIC 0 の有無
- バス: 種類、サブネット、ゲートウェイ（ゲスト専用では netd の DHCP と DNS のアドレス）、ルーター、外への出方、つながっている VM
- Mac: 参加しているネットワーク

## 4. 作り

- 図の中身（バス、行、点、並び）は AgentKit の `NetworkMap` が、VM の一覧、HanaLima のネットワーク、Lima のネットワーク、リースから作る。画面に依存しないので単体テストで確かめる。MCP の `inspect` から使う余地も残る
- 描画は SwiftUI のビューと `Path` で、配置は固定の寸法で自前に計算する。自動配置のエンジンや Web の図のライブラリは使わない（構成は「VM × ネットワーク」の形に決まっていて、表のように並べれば足りる）
- 置き場所はネットワークの画面で、ツールバーの切り替えで一覧と構成図を行き来する
- 画面確認: `HANALIMA_SNAPSHOT_SELECT=networks HANALIMA_SNAPSHOT_MAP=1`（`HANALIMA_SNAPSHOT_MAPSELECT=<VM かネットワークの名前>` で選んだ状態、`HANALIMA_SNAPSHOT_DARK=1` でダークモード）

## 5. 2 段目: 疎通の結果を重ねる

2026-11-16 の設計。Claude と Codex がそれぞれ独立に設計して突き合わせた。図の配線は設定のまま残し、その上に「いつ、どこから、どこへ、何を試して、どうだったか」を重ねる。結果は、試した 1 回のやり取りの記録で、ネットワーク全体の健全さも、届かないこと（隔離）も示さない。

### 5.1 何を確かめるか

検査はすべてゲストの中から行う（Mac から VM へは試さない）。ゲストの NIC は MAC で引き当てる（`/sys/class/net/*/address`。`eth0` のような名前を決め打ちしない）。見つからない NIC は「確かめられず」にする。ping はその NIC に縛り（`ping -I <インターフェース> -c 2 -W 2 <アドレス>`）、名前でなく数字のアドレスに送る。縛らずに送ると、別の NIC（NIC 0 など）を通って返ってきても「届いた」になるため（docs/14 の検査は縛っていない）。

| 図の要素 | 試すこと |
|---|---|
| NAT・ホストオンリーの点 | その NIC から Mac のアドレス（ゲートウェイ）へ。加えて、同じネットワークの VM 1 台（下の選び方）へ |
| ゲスト専用の点 | ルーターへ（自分がルーターなら除く）。加えて VM 1 台へ。netd のサーバーのアドレスは ICMP に答えないので試さない |
| ブリッジ、Lima、外のソケットの点 | 届く先を HanaLima が知らないので試さない（設定だけのまま） |
| 外への出口（NIC 0、vzNAT、ゲスト専用のルーター） | 利用者が入力した外の IPv4 アドレスがあるときだけ、その出口の NIC に縛って ping する。入力が無ければ試さない（docs/14 と同じく、外の宛先を HanaLima が決めない） |

相手の VM の選び方: 同じネットワークの次の VM（図の行の順で、末尾は先頭へ戻る）。アドレスは予約か、その NIC の MAC で引いた期限内のリースで、1 つに決まるものだけを使う（VM の名前で引いたリースは使わない）。相手がルーターやゲートウェイと同じアドレスなら、2 度は送らない。1 台だけのゲスト専用ネットワークで、ルーターも無ければ試す先が無い（設定だけ）。

あわせて、各 NIC がゲストの中で持っている IPv4 を読み、右の欄に「ゲストのアドレス」として出す。ブリッジの IP も分かるようになる。ただし、アドレスがあることは疎通の証拠にしない。

DNS（`lima-<名前>.hanalima`）と HTTP は、この段階では確かめない。名前の解決と到達が混ざり、HTTP はどの出口を通ったか特定できないため。

### 5.2 状態と描き方

点ごとに、その NIC から試した結果をまとめる。

| 状態 | 描き方 | 意味 |
|---|---|---|
| 設定だけ | 今の点のまま | 試していない、試す先が無い、飛ばした |
| 届いた | 点に緑のチェック | 表示した検査がすべて通った |
| 確かめられず | 点に黄色の「?」 | 試したが通らなかったか、結果が得られなかった（時間切れ、コマンドが無い、NIC が見つからない）。届かないことの証明ではない |
| 古い | 薄くして時計の印 | 前の結果を時刻つきで残している |
| 確かめ中 | 回転する印 | 実行中だけ |

点の色（Mac は青緑、ルーターは紫）はそのままにし、印を重ねる。2 つの NIC が 1 つの点にまとまっているときは「1/2」のように出し、片方だけ通ったものを緑にしない。NIC 0・vzNAT の札には出口の検査の結果だけを出す。バスの見出しは件数（「届いた 3・確かめられず 1」）にとどめ、「正常」とは書かない。右の欄に、検査ごとに、出した NIC、宛先と出どころ（予約・リース・ゲートウェイ・入力）、時刻、通らなかった理由を出す。色だけに頼らず、印とアクセシビリティのラベルを付ける。

古くなる条件: その VM の起動・停止・一時停止・休止、名前の変更、NIC・ネットワーク・ルーター・予約の変更、ネットワークの保存と削除（netd が起動し直す）。一度古くなった結果は、元の状態に戻っても古いまま（一時停止して再開した、ネットワークを変えて戻した）。選択や並びの変更では古くしない。ゲストの中だけの変更（ファイアウォールなど）は分からないので、結果には確かめた時刻を添える。時間だけで古くする規則は置かない。実行中に構成が変わったか、どれかのネットワークを保存・削除したら、その VM の回の結果は捨てる。ネットワーク単位で確かめ直したときは、ほかのネットワークの結果を元の時刻のまま残す。ping する先が無い VM でも、ゲストのアドレスは読む（ブリッジの IP のため）。ネットワーク単位の検査では、外のアドレスには ping しない。

### 5.3 いつ、どう実行するか

自動では実行しない。ボタンで範囲を選ぶ: ツールバーの「すべて確かめる」、VM の行の「この VM を確かめる」、バスの見出しの「このネットワークを確かめる」。実行の前に、対象の VM、飛ばす VM とその理由、外の IPv4 の入力欄を 1 枚のシートで示す。

- 1 台ずつ順に実行する（並列にしない）。各 VM の直前に、実行中・準備完了・一時停止していない・処理中でないことを確かめ直し、通らなければ理由を付けて飛ばす。停止中・休止中の VM を起動したり、一時停止を再開したりはしない
- ゲストのスクリプトは `runGuestScript`（ログインユーザー、処理中の印、時間の上限）で実行する。実行中、その VM の起動・停止はできない。1 台の上限は 60 秒、1 つの ping は 2 秒
- 中止は、次の VM へ進まず、実行中のスクリプトを止める（Mac 側の `limactl` を終えるだけで、ゲストの中のプロセスが終わったかは分からない）。済んだ VM の結果は残し、途中の VM の結果は捨てる
- 「この VM を確かめる」では、その VM の中でだけ実行する。相手の VM の中では何も実行しない

### 5.4 結果の置き場所と MCP

結果はアプリのメモリに置き（画面を移っても残り、アプリを終えると消える）、構成とは別に、時刻、構成の世代、検査の中身、短い理由を持つ。ファイルには書かない。

画面のボタンは利用者自身の操作なので、承認は要らない。MCP には新しい道具を足さない。あとで `inspect` から最後の結果を読めるようにする余地はあるが、読むことで検査が走ることはしない。

### 5.5 作り

- `TopologyVerification` から、検査の記述（どの VM で、どの NIC から、どこへ、何を）と、POSIX の sh を書き出す部分、`HLCHECK` の読み取りを取り出して共通にする。`scripts(for: TopologyPlan)` はその上に残し、MCP の構築後の検査の振る舞いは変えない
- 今の構成から検査の記述を作る部分を AgentKit に足す。入力は `NetworkMap` と、NIC ごとの MAC とアドレス（図の点は NIC をまとめるので、それとは別に持つ）。偽の `TopologyPlan` は作らない
- 実行と結果の管理は AppModel の 1 か所に置き、ビューは描くだけにする

### 5.6 試験

- 単体: 検査の記述の作り方（相手の選び方、ルーター、1 台だけのネットワーク、ブリッジ、隔離、user-v2 が NIC 0 の代わりのとき、同じネットワークの 2 つの NIC、古いリース）、スクリプトを sh で走らせたときの出力（NIC の引き当て、`-I`、コマンドが無いとき、時間切れ）、状態のまとめ方（1/2、古くなる条件、実行中に構成が変わった結果を捨てる）
- E2E（`MapChecksEndToEndTests`）: 使い捨てのゲスト専用ネットワークにルーターとクライアントを置き、図から作った検査を `limactl shell` で実行して、NIC に縛った ping が届くこと、ゲストのアドレスが読めること、ルーターを止めるとクライアントの検査が確かめられずになること。2026-11-16 に Alpine と Ubuntu LTS で通過
- 画面確認: `HANALIMA_SNAPSHOT_MAPCHECKS=1`（Debug ビルドだけ。ゲストでは何も実行せず、見本の結果を入れる）

### 5.7 入れないもの

全組み合わせの ping、サブネットの走査、速度の計測、パケットの採取、自動の修復、経路の変更、ゲストへのツールの導入、結果の履歴、新しい MCP の道具。DNS と HTTP の検査は後回し。
