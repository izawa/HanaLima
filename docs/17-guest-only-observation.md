# ゲスト専用ネットワークの観測

2026-11-16 の設計と実装。ゲストの中でネットワークのプログラムを作っているときに、ネットワークの側から何が流れているかを見られるようにする。最初の段階は、netd のスイッチで数えることと、パケットの記録（pcap）。遅延・損失・切断を入れる機能はその次の段階で、ここでは入れる余地だけを残す。Claude と Codex がそれぞれ独立に設計して突き合わせた。

## 1. 対象

ゲスト専用ネットワークだけにする。netd 自身がスイッチなので、そのセグメントを流れるフレームをすべて見られる。NAT・ホストオンリー・ブリッジは vmnet を通るので、netd に見えるのは自分の中継だけで、セグメント全体ではない。意味の違う数を同じ画面に並べないため、後回しにする。

## 2. 数えるもの

数える単位は「ポート」で、netd への 1 本の接続（VM の 1 つの NIC）。名前は netd の起動ごとの ID と接続の番号で、MAC は表示のための手がかりにとどめる（1 つの接続が複数の MAC を名乗ることがある。今のゲスト専用の接続は MAC を `-` と記録している）。VM が接続し直すと新しいポートになる。

ポートごとに、起動からの累計のフレーム数とバイト数（Ethernet のフレームの長さ。netd との間の 4 バイトの長さは含めない）を持つ。

| 数 | 意味 |
|---|---|
| ゲストから | ゲストが送ってきたフレーム（中身の確かめや netd の応答より前） |
| ゲストへ | ゲストへのソケットに書けたフレーム（ゲストが受け取って処理したことまでは示さない） |
| 落とした（キューが満杯） | 宛先の送信キュー（512 フレーム）が満杯で捨てたもの |
| 落とした（切断） | 切断の後か、切断の途中で捨てたもの、書きかけで終わったもの |
| 壊れたフレーム | 14 バイトに満たないもの（「ゲストから」にも数える） |

セグメント全体では、ほかに次を数える: netd が答えたフレーム（DHCP・ARP・DNS）、宛先の決まらないフレーム（全ポートに送ったもの）、送り先の無かったフレーム。切断したポートの数もセグメントの合計に残す。全ポートに送ったフレームは、ゲストからの 1 つと、宛先ごとの「ゲストへ」か「落とした」として数える。1 つの「落とした率」は出さない（書き込み待ちのフレームがあるので、送った数と届いた数の差は落としたことを意味しない）。

## 3. アプリへの渡し方

netd の状態のファイル（`NetworkDaemonStatus`）に、数を入れる欄を足す。netd の起動ごとの ID、通し番号、時刻とともに、1 秒に 1 回と接続の変化のときに書き換える。書き込みは転送の処理とは別のスレッドで行い、転送を待たせない。

アプリは、構成図を表示している間だけ 1 秒おきにこのファイルを読み、2 回の読み取りの差から毎秒の数を出す。netd が起動し直したか、ポートが入れ替わったら差を取り直す。3 秒以上更新の無い数は「古い」と出し、0 とは出さない。古い版の netd（この欄が無い）なら「ヘルパーが古い版です」と出す。数を見るために VM を再起動させることはしない（古い版のヘルパーは、VM が離れたときに入れ替わる。docs/04）。

## 4. パケットの記録

**操作は制御用のソケットで行う。** netd のソケットは VM のフレームの通り道なので、命令を混ぜない。launchd の登録に 2 つ目のソケット（`<名前>.ctl.sock`、0600、同じ UID だけ）を足し、1 接続 1 行の JSON で `status`・`start`・`stop` を受ける（ドライバーの `hanalima-ctl.sock` と同じ形）。`start` は、ファイルと見出しを作って記録を始めてから、記録の ID を返す。2 つ目の `start` は「記録中」と断る。記録中は netd がアイドルで終わらない。アプリが終了しても、止めるか上限に達するまで記録は続く。このソケットへの接続でも launchd が netd を起動するので、VM の起動の前に記録を始めて、最初の DHCP から残せる。

**記録するもの。** セグメント全体を 1 つのファイルに記録する。ゲストから来たフレームを、中身を確かめる前に 1 回ずつ、netd が作った応答（DHCP・ARP・DNS）を送る前に 1 回ずつ。全ポートに送ったフレームを宛先の数だけ重ねて記録はしない。そのため、記録は「送られたもの」を表し、届いたことは示さない（落としたフレームも記録に残る）。

**形式。** 従来の pcap（Ethernet、リンク型 1、snaplen 65536、元の長さ、マイクロ秒の時刻）。多くのパケット解析の道具がそのまま開ける。

**上限と性能。** 64 MiB か 5 分の早いほうで止まる。転送の処理は、記録用の上限つきの入れ物（8 MiB）に入れるだけで、ディスクを待たない。入れ物が満杯なら記録から落とし、その数を数える（転送には影響しない）。ディスクに書けなくなったら記録だけを止める。

**置き場所と扱い。** `~/Library/Application Support/HanaLima/Captures/`（0700）に、ファイルは 0600 で作る。書いている間は `.partial` を付け、閉じてから外す（途中で落ちたら、途中のまま分かる）。記録の上限、落とした数、終わった理由を小さな JSON で横に置く。始める前に「全部の VM の通信の中身（パスワードなどを含みうる）がファイルに残る」と示す。中身をログに書いたり、どこかへ送ったりはしない。

## 5. 画面

構成図の右の欄に出す。

- バス（ゲスト専用）を選んだとき: セグメント全体の毎秒の数と累計、落とした理由ごとの数、netd が答えた数。「パケットを記録」と「止める」、記録中の経過時間・大きさ・落とした数。記録が済んだら「開く」（macOS が決めたアプリで開く）と「Finder で表示」
- VM を選んだとき: その VM の NIC ごと（接続ごと）のゲストから・ゲストへ・落とした数（切断した接続の最後の数も）
- 切断した接続（最近の 32 本まで）は、バスの欄の「切断した接続」に畳んで出す。切断の途中で落としたフレームは、送信キューの片付けが済んでから数に入れる
- 古い数（3 秒以上更新が無い）には注記を付け、毎秒の数は出さない
- 登録が古い版のヘルパーのまま（制御のソケットが無い）なら、記録のボタンの代わりに「仮想マシンをすべて止めると入れ替わる」と出す。記録の前の状態は netd が終わると消える（状態のファイルを消すため）ので、前の記録を開けるのは netd が動いている間だけ
- バスの見出し: 記録中の印。疎通の検査の印とは別に出す

## 6. 試験

- 単体: 1 対 1・全ポートへの送り・netd の応答・壊れたフレーム・接続し直し・キューの満杯・切断の途中での数え方、状態のファイルの古い形式との互換、毎秒の数の取り直し。pcap の書き出しを読み戻して確かめる。止まった書き込み先や失敗する書き込み先でも、転送が続き、記録だけが落ちること
- E2E（`ObservationEndToEndTests`、2026-11-16 に通過）: 使い捨てのゲスト専用ネットワークで、VM の起動の前に制御のソケットで記録を始め（launchd が netd を起動する）、Alpine 2 台の DHCP の要求と netd の応答、2 台の間の ping が記録に入ること、2 本の接続の数が増えること、2 つ目の記録は断られること。ゲスト専用ネットワークの E2E どうしは同時に流さない（`--no-parallel`）。以下は当初の案:
- E2E の案: 既存のゲスト専用ネットワークの E2E を広げる。VM の起動の前に記録を始め、DHCP・ARP・DNS と、印を付けた ping の往復が記録に入ること、数が増えること。止める、上限、アプリの再接続、アイドルでの終了、古い版のヘルパーとの共存

## 7. 次の段階（障害を入れる）への余地

数えること、記録すること、制御のソケットを、スイッチの転送から分けておく。ゲストから受け取った所、netd が作った所、届けた所、落とした理由の所を、はっきりした場所にしておく。障害は「受け取った」と「届けた」の間に入れるので、今の数の意味を変えずに足せる。制御のソケットに命令を足せば、すぐ効いて結果を返せる。

## 8. 入れないもの

MAC ごと・流れごとの数、VM ごとの記録、アプリの中のパケットの一覧、絞り込み（BPF）、記録のファイルの回転、数の履歴、NAT・ホストオンリー・ブリッジでの観測、障害を入れる機能（次の段階）。
